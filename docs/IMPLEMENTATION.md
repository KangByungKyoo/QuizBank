# QuizBank 구현 및 검증 · 2026-10-14

## 개발 단계

1. **기본 프로젝트**: Kotlin, Compose Material 3, Room, MVVM, 한국어 홈 화면 완료.
2. **문제은행**: 깊이 제한 없는 카테고리 관리, 문제 세 가지 유형 CRUD, 키워드/하위 카테고리 검색 완료. 입력 검증과 삭제 영향 확인, 외래 키 무결성 적용.
3. **시험**: 복수 카테고리 및 유형 선택, 랜덤/오답 우선, 5/10/20/전체 출제, 중복 방지, 정답/해설, 단답형 수동 판정, 결과 저장 완료.
4. **학습 관리**: 오답 횟수, 오답 재시험, 시험 이력, 전체/카테고리/문제별 통계 완료. 진행 중 시험도 Room에 보관.
5. **데이터 관리**: UTF-8 CSV 파싱·행별 검증·미리보기·확인 등록, JSON 버전 검증·미리보기·병합/덮어쓰기/교체 완료.

## 설계

- Category는 문자열 UUID와 parentId를 사용합니다. 반복문으로 하위 트리를 탐색하여 앱에서 깊이를 제한하지 않습니다.
- Question과 QuestionOption을 분리하며, 객관식 정답은 내부적으로 0부터 시작하는 보기 위치를 저장합니다. CSV 사용자 입력은 1부터 시작합니다.
- ExamSession/ExamAnswer는 완료한 시험의 결과를 저장합니다. 당시 문제, 입력, 정답, 해설, 카테고리 경로를 복사하여 문제 수정/삭제 이후에도 기록이 유지됩니다.
- ExamDraft는 진행 중 문제 순서와 제출 답안을 저장합니다. 큰 시험 데이터를 SavedStateHandle Bundle에 넣지 않습니다.
- 삭제된 문제/카테고리 참조는 SET_NULL, 보기 및 하위 카테고리는 CASCADE입니다. 깊은 카테고리는 잎부터 삭제해 SQLite 재귀 트리거 제한을 피합니다.
- Repository가 Room 트랜잭션을 담당하고, 도메인은 계층/출제/채점/CSV/JSON 검증을 담당합니다. ViewModel은 화면 상태 및 비동기 작업을 관리합니다.
- 백업 복원은 전체 계획 검증 후 한 트랜잭션으로 반영합니다. 실패 시 기존 데이터가 유지됩니다.
- 파일 접근은 Storage Access Framework를 사용합니다. 인터넷 및 광범위한 저장소 접근 권한이 없습니다.

## 초기 구현 검증 결과

최종 동작 검증 명령:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:connectedUiTestAndroidTest --console=plain
```

- **단위 테스트 12개 통과**: 계층 탐색, 순환/중복 방지, 1,201단계 카테고리, 보기 검증/순서 보존, 단답형 채점, 중복 없는 출제, 오답 우선/전용 출제, 수동 판정, 시험 직렬화, UTF-8 BOM/쉼표/따옴표/줄바꿈 CSV, 오류 행 처리, JSON 왕복/검증/병합.
- **실제 Android 16 스마트폰 테스트 7개 통과**: 화면에서 문제 등록 및 시험, 객관식/OX/단답형과 수동 판정, Room 재개방 후 문제/오답/진행 중 시험 유지, CSV 자동 카테고리 생성, 시험 중복 저장 방지, 문제 수정/삭제 후 기록 보존, JSON 복원 및 실패 시 데이터 보존, 1,051단계 카테고리 삭제, ContentResolver 파일 입출력.
- **debug APK 빌드 성공**.
- **lint 오류 및 경고 없음**. Android 26~30의 백업 설정까지 명시했습니다.
- 스마트폰 세로 1080×2340 스크린샷을 확인했습니다. 홈, 문제 풀이, 정답 확인, 시험 결과가 `preview/`에 있습니다.

테스트는 별도 `.uitest` 앱과 전용 임시 데이터베이스를 사용했습니다. 실제 사용자 데이터베이스에 샘플이나 테스트 기록을 넣지 않았습니다.

## 발견 및 수정한 사항

- 초기에는 AGP 9.4와 SDK 37을 사용했으나, 사용자 Android Studio의 지원 범위에 맞춰 AGP 8.10.1과 SDK 36으로 조정했습니다.
- 화면 하단 알림이 시험 시작 버튼과 겹칠 수 있어 알림 높이를 화면 레이아웃에 반영.
- 문제 등록/답안 제출 후 키보드를 닫아 다음 화면의 버튼을 가리지 않도록 처리.
- 매우 깊은 카테고리의 삭제 시 SQLite 트리거 재귀 제한을 피하도록 삭제 순서를 조정.
- 진행 중 시험은 데이터베이스에 저장해 프로세스 종료 후 재개 및 대용량 Bundle 문제 방지.

## 남은 검증 및 제한

요청한 1~5단계의 기능을 구현했습니다. 가져오기 파일 크기 제한(10MB), 대규모 데이터의 메모리 기반 통계/검색, 다양한 파일 선택기 제공자, TalkBack/큰 글꼴/API 26 실기기 검증은 README의 현재 제한을 참고하세요. 스토어 배포용 서명은 아직 구성하지 않았습니다.


## Android Studio 호환성 수정

AGP 8.10.1 / Gradle 8.11.1 / Kotlin 2.0.21 / SDK 36으로 변경했습니다. AndroidX도 호환 버전으로 조정하고 Room 코드 생성은 KAPT를 사용합니다. 앱 기능과 Room 데이터베이스 구조는 유지했습니다.

호환성 수정 검증: assembleDebug, testDebugUnitTest(12개), lintDebug, assembleUiTestAndroidTest 성공. Room schema identityHash는 수정 전후 48c9f663a09c2cf2a917e069a1f863fb로 동일합니다. lint는 오류 0개, 버전 업데이트 및 KSP 전환 안내 경고 9개입니다. 기기 테스트 재실행은 연결된 기기가 없어 수행하지 못했습니다. output의 전달용 APK도 새 빌드로 갱신했습니다.
